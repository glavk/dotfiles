# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A personal dotfiles repo. The only tracked content of substance is `homebrew/Brewfile` (a Homebrew Bundle manifest) and its auto-generated `homebrew/Brewfile.lock.json`. Almost every change to this repo is an edit to the Brewfile.

There is **no installer, bootstrap script, or symlink setup** here. Files like `.zshrc` or `config` that may appear in the working tree are untracked scratch and are not kept in sync with `~/.zshrc` or `~/.ssh/config` — do not treat them as authoritative or assume editing them affects the live shell/SSH config.

## Common commands

Run from the repo root:

- `brew bundle --file=homebrew/Brewfile` — install everything in the Brewfile.
- `brew bundle check --file=homebrew/Brewfile` — verify all entries are installed (exit 0 = clean).
- `brew bundle cleanup --file=homebrew/Brewfile` — list installed formulae/casks not in the Brewfile (add `--force` to actually uninstall).
- `brew bundle dump --file=homebrew/Brewfile --force` — regenerate the Brewfile from the current system. **Avoid** as a default workflow: it flattens the hand-organized section comments and drops the commented-out / `# TODO:` lines.

`homebrew/Brewfile.lock.json` is auto-generated by `brew bundle`; never edit it by hand.

## Editing the Brewfile

- The file is organized by category with `## Section` header comments (`## Programming languages`, `## Kubernetes`, `## AI`, `## Hashicorp tools`, etc.). Place new entries in the matching section rather than appending at the bottom.
- Commented-out lines (`#brew "foo"`) and `# TODO:` markers are intentionally retained as a record of "tried this / removed this / considering this". Don't tidy them up unless asked.
- Taps go at the top. `brew` lines use unquoted formula names; non-default taps use the full path (e.g. `brew "hashicorp/tap/terraform-ls"`). `cask` lines for the same.

## Commit conventions

Single-line, lowercase conventional commits — overwhelmingly `feat: add <thing>` and occasionally `fix: ...`. Combine related changes in one subject (`feat: add X and remove Y`, `feat: add element and disable opentofu`). Match this style; don't introduce scopes, bodies, or Title Case.
